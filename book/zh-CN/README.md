# 全书脉络

状态：结构草案，尚非正文目录定稿。

核心论点：不必先成为程序员，也可以借助 AI，把自己熟悉的工作方法变成适合自己的工具。

## 第一部分：你熟悉的工作，就是起点

没有编程经验，不等于没有制作工作工具所需的经验。从原来的工作过程出发，辨认反复出现的麻烦，说明自己怎样判断结果，理解 AI 可以承担哪些工作。

## 第二部分：先把一件工作做顺

从一个具体环节开始，先获得有用的结果。以工作截图作为较小的起步实践，同时收紧主案例的第一版范围。比较现成软件、一次性处理与可重复使用的工具，按需要复用成熟库。

## 第三部分：让工具懂你的工作

通过现有材料、例子和结果，逐步说明个人规则。以汇报模板、输入数据和输出要求展开，讨论空白、分类、日期与单位等细节。票据案例帮助读者把相同方法迁移到另一类文件。

## 第四部分：不合用的时候，怎样继续

程序打不开、结果遗漏、修改后旧功能失效，都需要具体处理。结合能够复现的问题，解释怎样保留现场、描述差异、缩小范围并恢复能用的版本。

## 第五部分：让工具进入每天的工作

用新一批材料检验工具。讨论结果核对、原件保留、再次使用、规则变化和简单维护，按用途保存为脚本、skill 或小工具。

## 阅读与动手的关系

各章按 [本书的写作方法](../../docs/writing-method.md) 起草与审阅。先明确本章帮助读者作出的判断，再安排解释、案例和必要操作。

正文保留影响理解和判断的操作、对话与结果对比。随工具变化较快的安装和界面步骤放入配套资料。

每个案例会安排替换文件或修改规则的练习，帮助读者过渡到自己的工作。具体章节与练习仍需通过试做和样章调整。
