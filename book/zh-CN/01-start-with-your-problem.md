# 第 1 章　把眼前的麻烦告诉它

> 样章讨论稿。以下情境、对话和执行过程为教学设计，尚未实测。

你记得看过一份培训通知，里面写着周五之前要交报名材料。现在想再看一眼需要交什么，却找不到那份文件了。

电脑里有几个叫「通知.pdf」的文件。有的在下载文件夹，有的放进了不同月份的资料里。你点开一个，不是；再点开一个，是去年的。原本只想确认一件小事，又开始翻来翻去。

这时，你打开编程助手，问了一句：

> 我找不到一份培训通知了，只记得里面说周五之前要交材料。应该在下载或者培训资料文件夹里。你帮我找找，我不会编程。

开始这段对话，你手边只需要一台电脑和一个已经能用的编程助手。至于用什么命令查、怎样读取文件，可以交给它调查。

助手先确认能否访问这两个文件夹。能访问时，它可以直接在这个范围里查找；缺少权限时，才需要你按当前工具的方式授权或选定文件夹。它不能凭一句话看到电脑里的所有内容。

你补充：「只找文件，别改里面的内容，也别挪位置。」

拿到访问条件后，助手开始检查这两个文件夹及其子文件夹，查找与培训有关的资料。它自己选择可用的搜索工具，结合文件名和正文缩小范围；需要批量读取 PDF 时，可以利用现成的读取工具，必要时编写并运行一个小程序。

这些查找和处理不需要你逐份点开文件，也不用你先列出一套搜索步骤。编程助手能够调用工具、运行程序，并把执行结果用于后续判断。Claude Code 的官方文档介绍了这一过程；具体可用能力仍取决于工具和权限。[工作方式说明](https://code.claude.com/docs/en/how-claude-code-works#the-agentic-loop)

你在执行记录里看到，它开始搜索「周五」，随后又检查「星期五」「报名」「提交材料」等线索。某份 PDF 没有读出文字，它记录下来，检查是否有其他读取办法。文件名相同的资料，它保留各自所在的位置，没有把它们当成同一份。

这里重要的变化是：助手会根据查到的内容，决定下一步怎么查。你给它的那句模糊描述，正在变成一连串实际操作。

中间也可能遇到程序跑不起来的情况。报错会先返回助手，它可以检查原因、调整方法，再运行一次。缺少软件时，由它检查当前环境和可用方案；安装需要额外授权，再说明要装什么、为什么需要。只有必须由你完成的操作，才交代你在哪里做、做完该看到什么。

如果你看见执行记录里有一串不懂的命令，仍然可以问：「这一步在干什么？」它应该用当前任务解释，比如正在检查能否读取 PDF。终端是输入文字指令来操作电脑的工具，运行环境是执行程序所需的软件条件。你可以在这次工作中逐渐认识它们。

在这个情境里，助手查到了两份相关通知：一份是去年的，一份是今年的。两份都有周五提交材料的要求。它把文件位置、页码和相关原文放在一起，并指出年份不同。

「你要找的是今年这一期吗？」

> 对，就是今年的。我想确认要交哪些材料。

这时需要你补充的是自己的意图。助手继续读取今年的通知，整理报名材料，把每项对应的原文位置一并给出。你打开它指出的文件，核对培训名称、年份和报名要求，确认这就是要找的那一份。

如果仍有资料没能读取，助手也应该交代哪些没有检查到。找到了一个候选文件，与已经查完全部资料，是两件事。你据此判断现在的结果是否够用，还是需要继续查。

到这里，你没有指挥它逐个翻文件，也没有替它处理每一条报错。你说出了麻烦，提供了访问范围，补充了只有自己知道的信息，最后确认结果。搜索、读取、运行和调整方法，由助手承担。

等报名材料确认了，你又看了一眼那个放满资料的文件夹。今天找到的是这一份，下个月要找另一份呢？

于是，你接着问：

> 这种事我经常遇到。能不能让我以后输入几个字，就看到相关文件和位置？

这次，你开始需要一个能反复使用的办法了。助手可以先调查现成软件能否满足，再根据不合用的地方，考虑做一个适合你的小工具。

下一章，我们从这里接着做。
