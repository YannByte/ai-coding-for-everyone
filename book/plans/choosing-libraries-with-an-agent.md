# 样章材料卡：先找成熟实现，再让 AI 补上需要的部分

任务 ID：`choosing-libraries-with-an-agent`。对应第三部分第 9 章。正文见 [样章](../zh-CN/09-choosing-libraries-with-an-agent.md)，状态见 [工作状态](../workflow.json)。

## 读者、问题与论点

面向有无编程经验、想给已有软件增加功能的读者。用文件清单增加 PDF 正文搜索的教学情境，说明为什么复杂或需长期打磨的能力应优先调查成熟开源实现，再让助手配置、适配和补齐具体缺口。

本章判断：AI 围绕当前目标生成代码、运行有限检查，不保证覆盖真实使用的边界情况；优先利用有维护与测试依据的开源项目和库，沿用已有处理经验，再验证自己的用法。结果应说明哪些能力复用、哪些需要补写、已知边界及后续更新方式；不承诺开源必然更可靠或禁止自写简单功能。

登记为 argument。情境没有代码或附件，也没有选定产品、版本与执行环境；不能作为跟做教程。沿用文件工具作为读者熟悉的对象，不确立全书主项目，不改写第 13 章样本的内容或运行历史。

## 材料与证据

- 教学设计：三个独立命名的单页 PDF，分别为可提取文字且有关键词、可提取文字且无关键词、仅有扫描图像且肉眼可见关键词；示例结果均为预期或条件推演。
- Claude Code 官方工作方式：工具返回进入后续处理过程；作为机制说明，不保证本书情境有效或全部产品能力相同。
- pypdf 官方首页与文字提取文档：候选库的用途、文字提取与 OCR 的区别及提取限制。仅作候选示例，不声称完成选型、维护审查或实测。
- PyPA Dependency specifiers：依赖可附带版本与环境约束，用于解释为何要保留安装与版本记录。
- Chen 等 2021 年代码模型论文第 2 节：生成与执行测试的区别；不引用旧成绩评价当前工具。Anthropic 上下文工程：当前信息需要主动读取与管理，不据此断言具体错误。
- pypdf 测试文档：样本测试与旧问题关联，说明可查的验证积累；未运行其测试，不证明完整覆盖或优于自写。
- GitHub 仓库许可说明：公开可见与许可授权有区别；不代替具体选型的许可核查。
- 正文的取舍方法属于编辑建议，不推导效率数字或普遍效果。来源定位登记到证据清单。
