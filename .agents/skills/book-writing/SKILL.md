# 本书写作

帮助没有编程背景、经常使用电脑工作的人，理解怎样用 AI 做出适合自己的工作工具。把 ASD-STE100 的可迁移原则用于整本书，而不只用于仓库说明或操作步骤。中文和其他语言按各自语言习惯表达，不宣称完整符合英文标准。

## 开始前

读取目标目录的 AGENTS.md。以 [项目定位](../../../docs/project.md)、[全书脉络](../../../book/zh-CN/README.md) 和相关案例说明为上下文。保留用户已经确定的范围，不把书改成产品说明、开发者教程或提示词汇编。

使用 [术语表](../../../docs/terminology.md) 统一概念。中文任务同时应用仓库中的 [中文写作技能](../tech-doc-style-chinese/SKILL.md) 与 [本书覆盖说明](../../../docs/chinese-writing.md)。本技能负责章节判断、叙述和审稿方法，中文技能负责具体语言与排版；上游文件保持独立。

## 按任务读取并执行

| 任务 | 读取 | 交付 |
| --- | --- | --- |
| 起草章节、案例或练习 | [写作方法](references/writing-guide.md) | 在已有范围内完成正文，标明证据与试做缺口 |
| 改写或润色 | [写作方法](references/writing-guide.md) | 保留事实、条件、逻辑和确定程度，修改用户指定范围 |
| 审稿 | [审稿标准](references/review-guide.md) | 按影响排序的问题、原文位置与可执行建议 |
| 翻译 | [翻译规则](../../../translations/AGENTS.md)、[审稿标准](references/review-guide.md) | 对齐术语与判断关系的译文，记录原文版本与审阅状态 |

起草或改写后，再用审稿标准检查交付内容。仅校对时只处理指定的错字、标点或术语，不自行重排整章。

## 写作时的关键判断

- 一章围绕读者需要作出的判断组织。用具体工作、材料、选择和结果支持论点；解释选择为何成立及其条件。
- 同一概念使用同一术语。明确是谁、对哪个对象、做什么；区分读者动作、AI 回复和程序行为。
- 操作条件先于动作，结果给出核对依据。顺序动作分别交代，必要说明保留在读者作出决定的位置。
- 保留段落的因果、转折与自然叙述。不强制所有内容变成列表，不以中文字符数替代英文句长规则。
- 教学人物、数据和对话要标明性质。AI 的回复不构成执行证据；预期结果、作者试做和读者试做分别表述。
- 对缺失的事实或验证标记缺口，继续完成有依据的部分；不补造结果、按钮、命令、耗时或读者反馈。

## 完成时

修改仓库文件后，按根目录规则执行检查。另行说明是否完成事实核对、试读或试做，以及尚存的限制。链接、格式和用词检查通过，不能作为文章易懂或案例有效的证明。

技能文件与参考资料随仓库维护，适用 [仓库许可](../../../LICENSE.md)。它们是本书的写作约定，没有收录或重新授权 ASD-STE100 标准全文。
