# 中文写作规则

本文件适用于本书的中文正文、案例、练习及配套说明。章节组织采用 [写作方法](writing-method.md)，交稿前执行 [审稿规则](review.md)。这些是仓库规则，由 AGENTS.md 按任务引用，作者和协作者直接遵循。

本文件根据 Fenng 的 [中文技术写作规范](https://github.com/Fenng/tech-doc-style-chinese) 改编，版权归原作者及相应贡献者所有。本文件及本仓库对它的修改采用 [MIT 许可](../LICENSES/Chinese-Writing-MIT.txt)；本书其他原创文档的许可见 [许可说明](../LICENSE.md)。

## 保留事实与限制

- 保留事实、逻辑、条件、例外、单位和必要风险说明，再调整结构、语气和排版。
- 不新增没有依据的日期、数字、耗时、能力、因果关系或结论。
- 保留「可能」「通常」「计划」表达的确定程度。缺少证据时标明待确认或待试做，不自行补全。
- 教学人物、数据和整理后的对话必须注明性质，不能写成真实亲历、原始引语或已验证效果。
- 引用、报错原文、代码、命令、路径、URL、字段名和配置值保持原样。对固定内容的修改建议单独说明。

## 用语与叙述

- 使用常用词和明确动词。将「优化」「智能处理」等笼统表达展开为具体对象、动作或判断依据。
- 一个段落围绕一个主要意思展开；保留段落之间的原因、条件、转折与推理。
- 句子保持清晰主干。指代可能混淆时，写出具体名称；区分读者操作、AI 回复和程序行为。
- 允许称呼读者为「你」。语气自然、克制，避免宣传口号、空泛形容和连续堆叠术语。
- 标题说明具体主题，不强制整齐句式。列表用于并列信息或操作顺序，不把全部叙述拆成列表。
- 必要技术名词在实际用途出现时解释。同一概念使用 [术语表](terminology.md) 中的首选表达，不为避免重复轮换同义词。
- AI 编程工具的通用称呼、Agent 概念与具体产品名按 [称呼规则](terminology.md#面向读者的称呼) 区分。检查修改时覆盖当前正文和项目入口；保留原文引用与历史稿。

## 操作与结果

读者必须知道的条件放在动作之前。一个步骤包含一个主要动作，写明对象和核对结果的办法；涉及覆盖、删除或上传时，先说明对象与后果。预期结果尚未验证时，不写成已经发生的事实。具体组织方式见 [写作方法](writing-method.md)。

## 标点、数字与留白

- 中文正文使用全角中文标点。引号使用「」，嵌套使用『』；作品名称使用《》。固定引用和官方名称保留原样。
- 中文与英文、数字、版本号、行内代码之间加一个半角空格，例如「使用 API」「等待 3 秒」。不修改代码内部或链接目标。
- 中文全角标点两侧不额外加空格。链接按显示文字判断留白。
- 数字与半角单位符号之间留空格，例如 `10 GB`、`200 ms`、`25 °C`。百分号和角度符号紧邻数字，例如 `50%`、`90°`。
- 不因排版换算单位、改变精度或增补年份。区别百分比与百分点，保留数值范围的边界和包含关系。
- 日期写作「2026 年 10 月 11 日」，数字时间保留 `15:30` 形式。有跨时区需要时注明已知时区，不猜测缺失信息。
- 完整句式的列表项使用句号，短语项可以不加；同一列表保持一致。

## Markdown 源文件

正文一段一行，长行交给编辑器软换行。代码、表格、标题、引用和明确的 Markdown 换行保留原有结构。处理留白或合并段落前，先保护这些内容，修改后逐处复核。

## 检查

在仓库根目录运行 `python3 scripts/check_repo.py`。它执行中文检查工具的测试和正文轻量检查。确定错字等错误会阻止检查通过；语气和称呼提示由作者判断，不启用 `--strict` 将所有提示当成错误。

单文件检查：

```sh
python3 tools/chinese-writing/scripts/lint_copy_rules.py README.zh-CN.md
```

合并段落前先检查，不默认批量改写：

```sh
python3 tools/chinese-writing/scripts/unwrap_md_paragraphs.py --check book/zh-CN
```

工具的来源见 [来源记录](../tools/chinese-writing/UPSTREAM.md)。检查器不能证明论点成立、文章好读或案例有效，仍需按审稿规则人工核对。
