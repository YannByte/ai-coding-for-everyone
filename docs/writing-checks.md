# 写作规则的自动检查

统一入口为 `python3 scripts/check_repo.py`，使用 Python 3.11 或以上版本与标准库，不需要联网或安装第三方包。[写作检查脚本](../scripts/check_writing.py) 已接入该入口与现有 CI。

## 哪些问题阻止通过

- [词表](vocabulary.json) 缺少必需字段、来源定位或核对日期；表达偏好被错误配置成硬性报错。
- 当前检查范围内出现已登记的确定产品误拼。固定引用、代码和路径不做替换。
- [翻译清单](../translations/manifest.json) 漏登英文编号章节、路径无效、正文哈希不符或审阅记录未绑定当前原文与译文。
- 标为完成人工审阅但没有登记人工审阅报告。报告是否真实、充分仍由人判断。

已有脚本继续检查公开文件、相对链接、案例材料、中文排版及工作状态，不重复实现。

## 哪些问题只提示复核

英文句长、段落长度、术语变体、精选 STE 词汇建议和专业词首次出现，都只给出 advice。英文编号项暂按操作候选使用 20 词阈值，其余段落按 25 词，每段超过 6 句提示；脚本不能判断编号项是否真是操作，不能识别句子的全部含义。

首次用词提示不表示缺少解释，也不会因附近有「means」或「是」就自动宣布解释充分。审阅者结合上下文检查，允许有理由地保留。脚本不重写文字、不根据建议生成通过结论，不声称符合 STE。

## 检查范围

默认只检查中英文首页、当前 `book/workflow.json` 登记的中文正文、翻译清单登记的英文正文。资料索引、术语表及审阅报告不参与词汇和句长检查，避免把反例与来源标题误判为正文。规则文件和报告仍接受仓库链接与记录检查。

Markdown 解析为保守子集：跳过代码围栏、缩进代码、引用块、标题、表格、HTML 注释、前置信息、链接及行内代码；行内双引号和中文引号内的原文也跳过。被跳过的提示词示例、表格和引用仍须人工检查。此脚本不是完整 Markdown 解析器，复杂嵌套格式或少见缩写可能漏报或误报；输出行号定位到相关段落起始行。发现边界问题时用可公开的最小样例补测试。

单独检查已入库的英文样章：

```sh
python3 scripts/check_writing.py --language en book/en/13-working-with-a-stuck-assistant.md
```

显式指定文件只改变正文扫描范围，词表和翻译登记的一致性检查仍执行。检查器返回 0 表示无确定错误，返回 1 表示有错误；advice 不阻止通过。

## 翻译版本与术语来源

翻译清单记录 source、translation、source_commit、source_sha256、translation_sha256、review、human_review。原文和译文的当前文件哈希必须与清单及对应审阅报告一致；人工审阅完成时还须提供 human_review_report。版本变化后先审阅差异，再创建记录并更新哈希，不以改哈希代替复核。当前清单只实现已开始的英文版本；新增语言时一起扩展检查及测试。

source_commit 只校验完整提交号格式，不联网抓取或验证浅克隆中不存在的历史对象。术语来源只检查字段和网址格式，不能证明网页支持该词义。更新词表时仍须阅读官方正文、记录定位，并审查适用语境。
