# 写作工程流程

目标是使每次写作都有明确输入、可检查的交付和可追溯的修改。已经确认的决定见 [项目范围](project.md)；只研究当前任务中的缺口，不重复讨论已经确认的决定；待定书名和案例不得写成定稿。

## 文件职责

| 文件 | 维护内容 |
| --- | --- |
| [项目范围](project.md) | 当前已确认决定和待定事项 |
| [全书脉络](../book/zh-CN/README.md) | 五部分顺序和论述递进 |
| [工作状态](../book/workflow.json) | 当前写作任务、阶段、正文位置、证据编号、审阅记录与待办 |
| 章节材料卡 | 选定任务后在 book/plans/ 建立，记录论点、材料、章节衔接与完成要求 |
| [证据清单](../book/evidence.json) | 重要说法、来源定位、核实状态；不把来源摘要当作正文 |
| [审稿规则](review.md) | 审阅方法、问题影响和通过依据 |
| [记录格式](record-formats.md) | 试做和审阅应保留的最少信息 |

案例 README 维护工作要求，素材清单维护公开输入输出。不要在进度文件中复制这两份内容。章名可以修改，任务 ID 保持稳定；任务 ID 不等于正式章节编号。只登记要推进的章节，不用空文件铺满全书。方向调整后尚未选择任务时，活动任务和章节证据可为空；历史记录不能自动继承为新方向的完成证据。

## 一次写作任务

1. 读取项目范围、当前材料卡、相应写作规则与证据原文。需要衔接时再读相关正文，不把所有历史聊天塞入上下文。
2. 检查已有材料与缺口。先完成能做的研究、素材制作或试做；事实尚未明确时保留待核实标记。
3. 按一个完整论述单元起草。AI 可以整理材料、提出反例、起草和改写；作者负责关键取舍，正文必须留下判断依据。
4. 分开做结构审稿、事实核对和语言校对，先修影响读者理解与操作的问题。审阅者只用 AI 时如实注明。
5. 对实践章节进行作者试做和读者试做。读者试做必须由符合定位的人完成；AI 模拟反馈只能作为编辑预检。
6. 保存正文及记录，更新状态、证据与材料卡中的衔接信息。完成本次修改后运行统一检查，再提交同一批变更。

AI 应在授权范围内推进。阶段要求是交付标准，不是每完成一步就向用户申请批准。未定事实不编造；用户明确要求的取舍优先于惯用工作流。

## 阶段与进入条件

| status | 含义 | 必要条件 |
| --- | --- | --- |
| preparing | 准备材料 | 材料卡存在，明确论点、材料和缺口；不要求已写正文 |
| drafting | 起草 | 正文文件存在；未证实说法仍可登记为 pending，正文同步注明 |
| revising | 修改与审阅 | 正文存在；依据问题记录修改，不自动表示完成任何审阅 |
| reader-testing | 可安排读者验证 | 结构、事实审阅通过；实践章节还须有作者试做通过记录与已核实的实际观察；事实证据已核实 |
| ready | 本轮可交付 | 上述条件满足，语言校对与读者验证通过；实践章节要求 reader-trial，论述章节要求 reader-review |

`ready` 仅表示登记的这一版本满足本轮交付条件，不表示全书完成、普遍有效或已发布。读者试做记录必须说明帮助程度和材料范围。

每份通过记录绑定正文的 SHA-256。正文变化后，从当前 reviews 列表移出旧记录，回到 revising 并复核受影响内容。旧记录按下文清理规则留在 Git 历史中。轻微校对也要确认原审阅结论是否仍适用，不能直接改哈希冒充复核。

## 清理过期内容

已被替代的方案、停用案例和旧版审阅报告留在 Git 历史中，不在当前目录另建归档副本。判断依据是内容是否仍适用，不是文件日期；仍支撑当前论述的来源、试做证据、许可与出处说明继续保留。

清理前确认要保留的内容已提交到 Git，未提交的必要内容先保存。随后删除过期文件，同步修正入口、链接、状态清单和检查脚本中的旧约束，再运行统一检查并提交。当前审阅记录以工作状态和翻译清单为入口；被证据条目引用的报告也要保留。

需要找回时，用 `git log --all -- 路径` 查找文件历史，用 `git show 提交号:路径` 查看仍包含该文件的版本。只在确有需要时恢复文件，并重新判断其是否适用。

## 证据与验证

证据分为设计（design）、外部来源（external）和实际观察（observation）。设计保持 planned，只能解释预期；外部来源和实际观察从 pending 开始，有来源及准确定位后才可登记为 verified。

外部来源核实表示「来源确实如此表述」，不等于其自述经过独立验证。作者试做也不能升级为普通读者验证。证据中的 claim 文本保留这些边界。

运行 `python3 scripts/check_workflow.py --status` 查看阶段和缺口。运行 `python3 scripts/check_repo.py` 执行统一检查。自动检查会拒绝未知证据编号、遗漏文件、未核实事实支撑的交付、缺少必要验证记录以及正文与审阅版本不一致。

检查程序不评判证据真实性、审稿质量或读者是否真正完成任务。最终仍按记录核对，不把填写字段当成完成工作。

## 跨章连续性与全书审阅

每张材料卡保留「依赖前文、首次解释、后续承接、不重复展开」四项。写完一章后，用实际正文修订这些项目；需要改变全书顺序时同步修改脉络。将少量经试读的正文选作语气参照，记录文件和版本，不模仿别人的个人文风。

整稿形成后，从正文反向列出各章实际论点，检查重复、跳步、术语漂移和贯穿项目的连续性。随后只向审阅者提供成稿及读者可获得的配套资料，检查这些材料能否独立说明书的主张。审阅不靠作者在现场补充解释才算有效；发生的帮助应记录。
